\subsection{Technical Architecture}

    \centering
    \includegraphics[width=1\linewidth]{Figures/System_Architecture.png}
    \caption{This graphic depicts the architecture of the artefact developed to test the hypothesis of this thesis. The system is based on the service oriented paradigm to increase reusability, error discovery and to manage complexity.}

This section presents the software artefact developed to test the hypothesis of this thesis. The artefact is exclusively written in programming language Python, with data analysis performed in Jupyter Notebooks. Python was chosen since it is a high-level programming language widely adopted in academia and industry, specifically in AI applications where Python is widely adopted and has recently risen to the most used programming language on Github \cite{Github_2024_Survey}. This system is built on a service-oriented architecture, illustrated in Figure \ref{fig:System_Architecture}, in order to provide modularity, promote reusability, facilitate maintenance, and reduce overall system complexity \cite{Niknejad_et_al_2020_Service_Oriented}.

The artefact consists of four types of components: i) Initialization ii) Orchestration iii) AI Agent Management iv) Data Layer. The whole system receives a configuration file as input and returns a log file which contains all interactions, texts, and choices of the agents.

In the \textbf{Initialization}, the config file which is a .yaml file is converted into actual objects. The .yaml file specifies the parameters of the experiment; an example configuration is depicted in figure \ref{fig:Example_Config}. The order of the items in the config file is not relevant from a syntactical perspective, and items are grouped semantically. In the first step the system validates the data of the config file, and either raises an error or creates instances of the Pydantic data model. The choice to use YAML configuration files was made to provide a human-readable format that facilitates experimental parameter modification without requiring code changes, thereby enhancing reproducibility and enabling non-technical researchers to configure experiments. Pydantic was selected as the data validation framework due to its comprehensive type checking capabilities and automatic data conversion features, which ensure experimental integrity by preventing invalid configurations from proceeding to execution.

The \textbf{Orchestration} layer serves as the central coordination mechanism for the experimental workflow. This layer implements a hierarchical management structure consisting of the Experiment Manager, Phase 1 Manager, Phase 2 Manager, and Language Manager. The Experiment Manager coordinates the complete experimental lifecycle, managing phase transitions and maintaining experimental state consistency while implementing OpenAI Agents SDK integration for comprehensive tracing capabilities. The hierarchical design was chosen to separate concerns between different experimental phases, enabling independent optimization and testing of each component while maintaining clear interfaces between phases. The Phase 1 Manager orchestrates parallel execution of individual agent familiarization processes, leveraging Python's asyncio framework to enable concurrent agent interactions with justice principle scenarios while maintaining isolation between participant contexts. This parallel design significantly reduces experiment execution time compared to sequential processing, which is crucial for large-scale experimental runs. The Phase 2 Manager implements sequential discussion coordination, managing turn-based communication protocols and voting mechanisms to facilitate group decision-making processes. The sequential nature of Phase 2 reflects the inherent requirement for agents to respond to previous statements in deliberative processes, making parallel execution inappropriate for this phase. The Language Manager provides multilingual support through dynamic prompt translation and localization capabilities, supporting experimental configurations in English, Spanish, and Mandarin, thereby enabling cross-cultural research applications.

The \textbf{AI Agent Management} subsystem implements a dual-agent paradigm, differentiating between participant and utility agents with distinct computational responsibilities. This architectural choice was made to separate experimental subjects from system utilities, ensuring that response parsing and validation do not interfere with participant agent behaviors. Participant AI Agents encapsulate the experimental subjects and feature configurable large language model backends with support for multiple provider ecosystems, including OpenAI and OpenRouter model configurations. The multi-provider support was implemented to enable comparative analysis across different AI architectures within single experimental runs, facilitating research into model-dependent behavioral variations. Each participant agent maintains agent-controlled memory systems with configurable character limits (default: 50,000 characters), enabling autonomous memory structure determination and content management. This design choice reflects the recognition that different agents may benefit from different memory management strategies, allowing for naturalistic agent behavior while preventing excessive memory usage that could impact system performance. Utility AI Agents provide specialized computational services through dedicated language model integration optimized for response parsing and validation tasks, typically configured with deterministic parameters (temperature = 0.0) to ensure consistent analytical outputs. The separation of utility functions into dedicated agents was implemented to maintain consistency in system responses while allowing participant agents to exhibit varied behaviors.

The \textbf{Data Layer} implements comprehensive observability and persistence mechanisms essential for experimental validity and reproducibility. This layer encompasses Data Capture, Logging Service, and OpenAI Traces components. The Data Capture component provides systematic collection and storage of experimental results, agent interactions, and decision outcomes through structured JSON serialization. JSON was selected as the storage format due to its flexibility in handling complex nested data structures while maintaining human readability for manual inspection. The Logging Service implements agent-centric logging infrastructure providing detailed behavioral tracking and interaction monitoring throughout experimental phases. This design enables researchers to trace individual agent decisions and interactions, facilitating detailed behavioral analysis and debugging. The OpenAI Traces integration enables detailed inspection of agent reasoning processes and interaction patterns through the OpenAI platform's native tracing capabilities, providing additional debugging and analysis capabilities beyond the custom logging system.

The architectural design incorporates several key technical characteristics that enhance experimental validity and system reliability. Asynchronous processing capabilities leverage Python's asyncio framework to optimize computational efficiency during parallel phases, while comprehensive error handling provides categorization and recovery mechanisms with configurable retry logic and graceful degradation capabilities. The model-agnostic design supports heterogeneous model configurations within single experimental runs, enabling comparative analysis across different AI architectures. Multi-layer validation ensures data integrity from configuration parsing through agent response processing, preventing invalid experimental states and ensuring reproducible results.
