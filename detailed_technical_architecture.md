This section presents a comprehensive technical analysis of the software artefact developed to empirically test the hypothesis of this thesis. The complete source code implementation can be accessed through the public repository \citet{Mueller_2025_Rawls_Github_Repo}. The artefact is implemented exclusively in the Python programming language (version 3), with analytical components developed using Jupyter Notebooks for interactive data exploration and visualization. The selection of Python was motivated by several technical and practical considerations: Python represents a high-level programming language that has achieved widespread adoption across both academic and industrial domains, particularly within artificial intelligence applications where it has recently emerged as the most utilized programming language on GitHub \cite{Github_2024_Survey}. Furthermore, Python's extensive ecosystem of scientific computing libraries, mature asynchronous programming capabilities through the asyncio framework, and robust integration with contemporary AI model providers through standardized APIs rendered it the optimal choice for this multi-agent experimental platform. The system architecture follows a service-oriented design paradigm, as illustrated in Figure \ref{fig:System_Architecture}, strategically implemented to provide modularity, promote component reusability, facilitate long-term maintenance, and systematically reduce overall system complexity through clear separation of concerns \cite{Niknejad_et_al_2020_Service_Oriented}.

\subsubsection{Architectural Component Taxonomy}

The artefact implements a four-layer architectural decomposition consisting of: i) Initialization Layer ii) Orchestration Layer iii) AI Agent Management Subsystem iv) Data Layer. The complete system operates as a configurable experimental pipeline that accepts a YAML-based configuration file as input and produces comprehensive JSON-formatted log files containing all agent interactions, textual communications, decision traces, and experimental outcomes. This input-output design enables reproducible experimental execution while maintaining complete observability of agent behaviors throughout the experimental process.

\subsubsection{Initialization Layer: Configuration Management and Object Instantiation}

The Initialization layer constitutes the foundational bootstrap mechanism responsible for configuration parsing, validation, and object instantiation. This layer implements a sophisticated two-stage initialization process that ensures experimental integrity from system startup through agent deployment.

In the configuration processing stage, the system accepts YAML-formatted configuration files through a robust parsing pipeline that leverages the Pydantic data validation framework for comprehensive type safety and constraint enforcement. The configuration schema defines experimental parameters including agent specifications (personality descriptions, model selections, temperature settings, memory limits, reasoning capabilities), utility agent configurations (model selection, temperature parameters for deterministic parsing), Phase 2 (Group Phase) parameters (maximum discussion rounds, income distribution ranges), multilingual support settings (language selection from English, Spanish, and Mandarin), income class probability distributions, and optional original values mode configurations for reproducible baseline experiments. The YAML format was specifically chosen to provide human-readable configuration specifications that enable experimental parameter modification without requiring code changes, thereby enhancing experimental reproducibility and enabling non-technical researchers to configure experimental conditions. The syntactic structure of YAML configuration files is order-agnostic, with parameters organized semantically into logical groupings that correspond to system components.

The validation pipeline implements multi-layer constraint checking through Pydantic's declarative validation framework. The system validates language support compatibility, ensuring selected languages correspond to available translation files and prompt templates. Agent configuration validation enforces unique naming conventions, validates model string formats for provider detection, ensures temperature parameters fall within valid ranges (0.0 to 2.0), confirms memory character limits are positive integers, and validates personality descriptions are non-empty strings. Distribution range validation ensures multiplier ranges contain positive values with proper ordering (minimum less than maximum), while income class probability validation confirms all probability values fall between 0.0 and 1.0 and collectively sum to 1.0 within acceptable floating-point precision tolerances. The validation process either raises detailed ConfigurationError exceptions with specific validation failure descriptions or proceeds to instantiate corresponding Pydantic model objects that serve as immutable configuration containers throughout the experimental lifecycle.

The object instantiation subsystem transforms validated configuration data into operational system components through a systematic initialization sequence. The process creates ExperimentConfiguration instances containing all validated parameters, instantiates AgentConfiguration objects for each participant AI agent with verified model strings and parameter constraints, initializes IncomeClassProbabilities objects with validated probability distributions, and establishes OriginalValuesModeConfig instances when baseline experiment modes are specified. This design ensures that all subsequent system operations work with validated, type-safe configuration objects rather than raw dictionary structures, thereby preventing runtime configuration errors and enabling comprehensive IDE support during development.

\subsubsection{Orchestration Layer: Hierarchical Experiment Management}

The Orchestration layer implements a sophisticated hierarchical management architecture designed to coordinate complex multi-phase experimental workflows while maintaining strict separation of concerns between distinct experimental phases and cross-cutting system services.

The Experiment Manager serves as the primary orchestration component, implementing comprehensive experimental lifecycle management through the OpenAI Agents SDK integration. This component generates unique experiment identifiers using UUID4 generation for traceability, initializes error handling frameworks with experiment-specific logging contexts, coordinates phase transitions with state consistency validation, maintains experimental state through structured context objects, implements comprehensive tracing through OpenAI's platform integration enabling detailed inspection of agent reasoning processes, and provides experiment summary generation with statistical analysis of agent behaviors and decision outcomes. The centralized management approach was chosen to ensure consistent error handling, logging, and tracing across all experimental phases while maintaining clear interfaces between phase-specific managers.

The Phase 1 Manager orchestrates parallel execution of individual agent familiarization processes, leveraging Python's asyncio framework to enable concurrent agent processing while maintaining complete isolation between participant contexts. The implementation utilizes asyncio.create_task() for concurrent agent execution, asyncio.gather() for result aggregation, and individual ParticipantContext objects to prevent cross-agent state contamination. Each participant agent receives an isolated experimental context containing unique agent identification, role descriptions derived from personality configurations, independent memory management systems, isolated bank balance tracking, and phase-specific state maintenance. The parallel execution architecture significantly reduces total experiment execution time compared to sequential processing, which becomes crucial for large-scale experimental runs involving multiple agents and extensive Phase 1 familiarization sequences. The implementation includes comprehensive error isolation mechanisms ensuring that failures in individual agent processing do not compromise parallel execution of other participants.

The Phase 2 Manager implements sequential discussion coordination, managing turn-based communication protocols and consensus-building mechanisms that facilitate structured group decision-making processes. The sequential architecture reflects the fundamental requirement for deliberative processes where agents must respond to previous statements, making parallel execution inappropriate for this phase. The implementation manages randomized speaking orders to prevent systematic biases in discussion initiation, implements turn-based communication with strict ordering enforcement, maintains group discussion state through structured GroupDiscussionState objects, coordinates voting mechanisms with preference aggregation, implements consensus detection algorithms, and provides fallback mechanisms for handling non-responsive agents or communication failures. The manager incorporates sophisticated validation statistics tracking including total statement requests, successful statement generations, failed validation attempts, retry attempt counts, and fallback statement utilizations, enabling comprehensive analysis of communication effectiveness and system reliability.

The Language Manager provides multilingual experimental support through dynamic prompt translation and localization capabilities, enabling cross-cultural research applications and international experimental deployments. The implementation supports three primary languages (English, Spanish, and Mandarin) through comprehensive translation file management, dynamic prompt loading based on experimental configuration, contextual translation of justice principle descriptions and experimental instructions, agent communication localization ensuring all agent interactions occur in the specified experimental language, and validation response parsing in language-appropriate formats. The multilingual architecture enables researchers to conduct identical experiments across different linguistic and cultural contexts, facilitating comparative analysis of justice reasoning across diverse populations while maintaining experimental protocol consistency.

\subsubsection{AI Agent Management: Dual-Agent Paradigm Implementation}

The AI Agent Management subsystem implements a sophisticated dual-agent architectural paradigm that strategically differentiates between participant agents (experimental subjects) and utility agents (system services) to ensure experimental validity while maintaining system functionality.

The Participant Agent subsystem encapsulates experimental subjects through a comprehensive wrapper architecture that provides advanced LLM integration, sophisticated memory management, and experimental state tracking capabilities. The implementation features configurable large language model backends with comprehensive provider ecosystem support, including native OpenAI model integration for models specified without provider prefixes (e.g., "gpt-4.1-mini"), and LiteLLM integration for OpenRouter and alternative providers identified by forward-slash notation in model strings (e.g., "google/gemini-2.5-flash", "anthropic/claude-3.5-sonnet"). The multi-provider architecture enables comparative analysis across different AI architectures within single experimental runs, facilitating research into model-dependent behavioral variations and performance characteristics. Each participant agent implements dynamic temperature parameter detection through automated capability testing, ensuring optimal model configuration regardless of provider-specific parameter support variations.

The memory management subsystem represents a sophisticated agent-controlled architecture that empowers agents to autonomously manage their own memory structures and content throughout the experimental lifecycle. Each agent maintains configurable memory systems with character limits (default: 50,000 characters, configurable per agent), enabling agents to determine optimal memory structures, content prioritization, and information retention strategies. The implementation includes comprehensive memory validation mechanisms with automatic retry logic (maximum 5 attempts) when memory updates exceed configured character limits, graceful degradation procedures for handling persistent memory management failures, and detailed memory state logging for behavioral analysis and debugging purposes. This design choice reflects the recognition that different AI agents may benefit from distinct memory management strategies, allowing for naturalistic agent behavior while preventing excessive memory usage that could impact system performance or incur unnecessary API costs.

The bank balance tracking system maintains experimental state for income distribution scenarios and decision outcome recording through structured financial state management. Each agent maintains isolated financial contexts with precise income tracking, distribution outcome recording, decision impact assessment, and historical balance evolution throughout experimental phases. The implementation ensures complete financial isolation between agents while enabling comprehensive analysis of economic decision-making patterns and justice principle applications.

The Utility Agent subsystem provides specialized computational services optimized for response parsing, validation, and system analysis tasks through dedicated language model integration. Utility agents are typically configured with deterministic parameters (temperature = 0.0) to ensure consistent analytical outputs and reliable system operations. The implementation focuses on structured response parsing from participant agent communications, validation of decision formats and constraint specifications, analysis of agent reasoning patterns for experimental evaluation, and generation of structured data objects from natural language agent responses. The architectural separation of utility functions into dedicated agents was implemented to maintain consistency in system analytical responses while allowing participant agents to exhibit varied behaviors and decision-making patterns, thereby preserving experimental validity while ensuring system reliability.

\subsubsection{Data Layer: Comprehensive Observability and Persistence}

The Data Layer implements sophisticated observability and persistence mechanisms essential for experimental validity, reproducibility, and comprehensive behavioral analysis through three integrated subsystems: Data Capture, Logging Service, and External Tracing Integration.

The Data Capture component provides systematic collection and storage of experimental results, agent interactions, and decision outcomes through structured JSON serialization. The implementation captures complete experimental configurations with all agent specifications and parameter settings, comprehensive Phase 1 results including individual agent responses, principle rankings, constraint specifications, and application outcomes, detailed Phase 2 discussion records with complete conversational histories, voting sequences, consensus formation processes, and final group decisions, temporal interaction sequences with precise timestamp recording for behavioral timing analysis, and error statistics with categorized failure analysis and recovery attempt documentation. JSON was selected as the primary storage format due to its flexibility in handling complex nested data structures, cross-platform compatibility for data sharing and analysis, human readability for manual inspection and debugging, and native support in Python and Jupyter Notebook environments for seamless data analysis workflows.

The Logging Service implements an agent-centric logging infrastructure providing detailed behavioral tracking and interaction monitoring throughout all experimental phases. The architecture captures individual agent inputs and outputs with complete request-response logging, memory state transitions with detailed character utilization tracking and content evolution analysis, decision-making processes with intermediate reasoning steps and final choice justifications, error occurrences with comprehensive context information and recovery attempt documentation, and system performance metrics including response times, retry attempts, and resource utilization patterns. The agent-centric design enables researchers to trace individual agent decisions and interactions with complete fidelity, facilitating detailed behavioral analysis, debugging complex multi-agent interactions, and identifying systematic patterns in agent reasoning and decision-making processes.

The External Tracing Integration leverages OpenAI's native tracing infrastructure to provide additional debugging and analysis capabilities beyond the custom logging system. The implementation generates unique trace identifiers for each experimental run, enables detailed inspection of agent reasoning processes through the OpenAI platform interface, provides comprehensive API call monitoring with request-response logging and performance metrics, and facilitates debugging of complex agent interactions through visual trace analysis tools. The dual tracing approach (custom logging plus external integration) ensures comprehensive observability while providing researchers with multiple analytical perspectives on agent behaviors and system performance.

\subsubsection{Advanced Error Handling and Validation Framework}

The system incorporates a sophisticated error handling and validation framework designed to ensure experimental reliability through comprehensive error categorization, automated recovery mechanisms, and graceful degradation procedures. The framework implements six primary error categories: Configuration Errors (validation failures, parameter specification issues), Agent Communication Errors (LLM API failures, response parsing issues), Memory Errors (character limit violations, memory management failures), Validation Errors (data format issues, constraint specification problems), System Errors (infrastructure failures, network issues), and Experiment Logic Errors (phase transition problems, state consistency violations).

Each error category implements severity-based handling strategies with Recoverable errors enabling automatic retry mechanisms with exponential backoff and configurable maximum attempt limits, Degraded errors allowing continued operation with reduced functionality and comprehensive error state logging, and Fatal errors requiring immediate experiment termination with detailed failure analysis and state preservation. The error handling system provides comprehensive context capture including error timestamps, operation descriptions, agent identifications, configuration parameters, and causality chains for complex error scenarios.

The validation framework implements multi-layer data integrity checking from configuration parsing through agent response processing, preventing invalid experimental states and ensuring reproducible results. The implementation includes schema validation for all data structures using Pydantic models, content validation for agent responses and decision specifications, constraint validation for justice principle applications and income distribution specifications, and consistency validation for experimental state transitions and agent context management.

This comprehensive technical architecture provides a robust foundation for conducting controlled experiments in AI-mediated distributive justice scenarios while maintaining experimental rigor through sophisticated error handling, comprehensive data collection, and detailed behavioral analysis capabilities. The modular design enables systematic investigation of agent behaviors across diverse experimental conditions while ensuring system reliability and facilitating reproducible research in the emerging field of computational social science and AI ethics.
