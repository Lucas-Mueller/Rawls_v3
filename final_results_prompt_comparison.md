## Alignment Opportunities

1. Add a stylistically parallel headline for consensus cases (e.g., `**CONSENSUS REACHED**`) before the sentence, so both scenarios start their status block with bold text instead of one using bold and the other using plain prose.
2. Ensure the random assignment sentence ends with a period by updating `translations/english_prompts.json:399` to mirror the punctuation the consensus sentence receives from code.
3. Consider appending a clarifying line in consensus runs (e.g., `Group selection applied directly; no random assignment.`) to match the level of detail in the no-consensus explanation block.
4. If visual symmetry is desired, evaluate inserting a spacer line after the consensus sentence (or removing one from the no-consensus block) so the probabilities header begins at the same vertical position in both flows.
5. Optional: introduce a neutral marker (e.g., `← RANDOM ASSIGNMENT`) for the no-consensus outcome row to mirror the `← YOUR GROUP'S CHOICE` marker, improving scannability when reviewing principle outcomes.

These adjustments would keep localized content centralized in `translations/english_prompts.json` while preserving the structural assembly defined in `core/services/counterfactuals_service.py`.

## Formatting Requirement

Going forward, the no-consensus presentation must match the consensus formatting conventions line-for-line (status header styling, spacing, punctuation, and summary markers). Treat the consensus-reached block as the canonical template and adjust the no-consensus path so the two prompts are visually interchangeable aside from their textual content.
